Arsitektur aplikasi web modern telah bergeser drastis dari server terpusat (*monolithic VPS*) ke jaringan komputasi terdistribusi di tepian jaringan (*Edge Computing*). Di **Majalengka Tech**, misi kami adalah menghadirkan portal komunitas developer yang dapat diakses dalam hitungan milidetik dari mana saja di seluruh Indonesia maupun dunia tanpa biaya infrastruktur yang membengkak.

Untuk mewujudkannya, kami merancang fondasi backend *serverless edge-first* menggunakan **NuxtHub**, **Cloudflare Workers**, **Cloudflare D1 (SQL)**, **Cloudflare R2 (Object Storage)**, dan **Better Auth**.

---

## 1. Konsep Edge-First dengan NuxtHub

**NuxtHub** adalah lapisan orkestrasi di atas Nitro dan Cloudflare yang menyederhanakan interaksi dengan sumber daya serverless. Alih-alih mengelola konfigurasi driver penyimpanan secara manual, NuxtHub menyediakan modul virtual yang seragam:

- `hub:db`: Abstraksi database SQLite berbasis Drizzle ORM yang terhubung langsung ke Cloudflare D1.
- `hub:blob`: Abstraksi penyimpanan berkas biner yang terhubung mulus ke Cloudflare R2.
- `hub:kv`: Penyimpanan key-value latensi sangat rendah untuk caching dan rate limiting.

### Menghilangkan Kompleksitas Lingkungan Dev vs Prod
Keuntungan terbesar yang kami rasakan adalah konsistensi lingkungan. Di laptop pengembang, NuxtHub mensimulasikan D1 dan R2 menggunakan SQLite lokal dan sistem berkas lokal. Ketika di-*deploy* ke Cloudflare Pages/Workers, kode yang sama tanpa perubahan baris apa pun langsung berbicara ke kluster Cloudflare D1 global dan R2 bucket produksi.

```ts [server/api/upload.post.ts]
import { blob } from 'hub:blob'

export default defineEventHandler(async (event) => {
  const session = await getUserSession(event)
  if (!session?.user) throw createError({ statusCode: 401 })

  // Berjalan di lokal via local fs, dan di production otomatis ke Cloudflare R2!
  const uploaded = await blob.handleUpload(event, {
    formKey: 'file',
    ensure: {
      maxSize: '8MB',
      types: ['image/png', 'image/jpeg', 'image/webp']
    },
    put: { prefix: 'Projek' }
  })

  return { pathname: uploaded[0].pathname }
})
```

## 2. Cloudflare D1: Database SQL Terdistribusi di Tepian Jaringan

Berbeda dengan database relasional konvensional yang berlokasi di satu data center (misalnya Singapura atau Jakarta), **Cloudflare D1** menempatkan basis data SQLite di ratusan PoP (*Points of Presence*) Cloudflare di seluruh dunia.

### Mengapa D1 Cocok untuk Showcase & Direktori Proyek?
1. **Latensi Kueri Super Rendah**: Pembacaan data proyek publik dilayani langsung dari server edge terdekat dengan browser pengunjung.
2. **Kesesuaian dengan Drizzle ORM**: Skema tabel didefinisikan secara deklaratif dalam TypeScript, memungkinkan *type-safe queries* yang mencegah kesalahan kueri SQL di waktu kompilasi.
3. **Migrasi Otomatis**: Setiap skema perubahan (misalnya migrasi `0002_better_auth.sql`) dieksekusi secara aman tanpa downtime.

## 3. Cloudflare R2: Aset Media Bebas Biaya Egress

Platform komunitas developer memungkinkan anggota memamerkan tangkapan layar (*screenshot*), logo, dan media presentasi proyek. Penyimpanan objek awan konvensional umumnya membebankan biaya transfer data (*egress bandwidth*) yang tinggi saat gambar dimuat berulang kali.

Dengan **Cloudflare R2**:
- **Nol Biaya Egress**: Pengunjung dapat memuat gambar showcase proyek beresolusi tinggi tanpa kekhawatiran tagihan membengkak.
- **Siklus Hidup Aset Bersih**: Kami mengimplementasikan *lifecycle hook* di mana penghapusan record proyek di database D1 secara otomatis memicu `await blob.delete(pathname)` pada bucket R2, memastikan kapasitas penyimpanan selalu optimal dan bebas file sampah (*orphaned files*).

## 4. Keandalan Autentikasi dengan Better Auth

Autentikasi di lingkungan V8 isolate (Cloudflare Workers) sering kali menjadi batu sandungan karena ketiadaan API Node.js standar. Kami mengintegrasikan **Better Auth** melalui `@nuxtjs/better-auth`:

### A. Otentikasi Sosial Tanpa Password
Pengembang dapat masuk secara instan menggunakan akun GitHub atau Google OAuth. Data sesi dan profil pengguna disimpan secara terenkripsi di tabel D1 (`user`, `session`, `account`).

### B. Sinkronisasi Melalui `runtimeConfig`
Untuk menjamin keamanan token enkripsi dan kredensial OAuth, seluruh rahasia sensitif dialirkan melalui Cloudflare Secrets dan dipetakan ke dalam `runtimeConfig` Nuxt:

```ts [server/auth.config.ts]
import { defineServerAuth } from '@nuxtjs/better-auth/config'

export default defineServerAuth(({ runtimeConfig }) => ({
  trustedOrigins: ['http://localhost:3000', 'https://majalengka.tech'],
  socialProviders: {
    github: {
      clientId: runtimeConfig?.oauth?.githubClientId,
      clientSecret: runtimeConfig?.oauth?.githubClientSecret
    }
  }
}))
```
